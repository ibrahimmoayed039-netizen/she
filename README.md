# نظام الشكاوى (تطبيق المواطن + تطبيق الموظف + برنامج الحاسوب)

## 1) إعداد Firebase (يفعله كل زبون مرة واحدة بحسابه)
1. أنشئ مشروعاً في https://console.firebase.google.com (أوقف Gemini وGoogle Analytics، غير مطلوبين).
2. **Authentication ← Sign-in method**: فعّل **Anonymous** و **Email/Password**.
3. **Firestore Database**: أنشئ قاعدة بيانات، ثم من تبويب Rules الصق محتوى `firestore.rules` واضغط Publish.
4. من Project settings أضف **تطبيق أندرويد واحداً** (أي اسم حزمة) ونزّل `google-services.json`.
5. **تطبيق المواطن (للتوزيع على الجمهور)**: حوّل `google-services.json` إلى Base64 (PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("google-services.json"))`) وأضفه في GitHub ← Settings ← Secrets and variables ← Actions باسم `CITIZEN_GOOGLE_SERVICES`. عند البناء يُدمج داخل الـ APK فيعمل مباشرة دون أي خطوة من المواطن. لكل زبون جديد غيّر قيمة السر وشغّل Actions من جديد.
6. **تطبيق الموظف**: افتحه وفي شاشة «ربط قاعدة البيانات» اختر الملف (أو الصق محتواه)، مرة واحدة لكل جهاز. وزر «تغيير إعدادات الاتصال» في شاشة الدخول لتغيير المشروع.

## 2) البناء (مرة واحدة فقط لكل الزبائن)
ارفع محتويات المجلد إلى جذر المستودع (بما فيه المجلد المخفي `.github`) في فرع `main`، ثم من تبويب **Actions** حمّل من Artifacts:
- `citizen-app-apk`  (تطبيق المواطن)
- `staff-app-apk`    (تطبيق الموظف)
- `desktop-installer` (مثبّت برنامج الحاسوب .exe)

الكود نفسه لجميع الزبائن، والذي يتغير فقط هو سر `CITIZEN_GOOGLE_SERVICES`. لا ترفع `google-services.json` إلى المستودع.

> ملفات APK موقّعة بمفتاح debug وتعمل للتثبيت المباشر. للنشر على Google Play تحتاج توقيع Release.

## 3) حسابات الموظفين
1. Firebase ← Authentication ← Users ← Add user (بريد + كلمة مرور).
2. انسخ **User UID** للحساب.
3. Firestore ← أنشئ مجموعة `staff` ← مستند رقمه = UID، وفيه حقل نصي `department` باسم القسم (مثال: `الكهرباء`).
   يجب أن يطابق اسم القسم تماماً ما هو مكتوب في إعدادات برنامج الحاسوب.

## 4) برنامج الحاسوب
1. ثبّته وافتح **الإعدادات**.
2. الصق مفتاح Claude API.
3. من Firebase ← Project settings ← Service accounts ← Generate new private key، ثم اختر الملف في البرنامج.
4. اضبط قائمة الأقسام واضغط **حفظ وإعادة الاتصال**. ستُحلَّل الشكاوى الجديدة وتُوجَّه تلقائياً.

## ملاحظات
- الصور تُصغَّر وتُحفظ داخل Firestore (لا حاجة لـ Storage المدفوع).
- التخزين المحلي: Firestore يحفظ كاشاً على الجهاز يبقى بعد الإغلاق ويعمل دون إنترنت، وإعدادات المواطن في SharedPreferences، وإعدادات الحاسوب في electron-store.
- مفتاح Claude وحساب الخدمة موجودان في برنامج الحاسوب فقط، لا في أي APK.

## طريقة التحليل في برنامج الحاسوب (الإعدادات ← طريقة التحليل)
- **Claude**: الأدق، يحتاج مفتاح API ورصيد.
- **محلي (Ollama)**: مجاني ويعمل دون إنترنت. ثبّت Ollama من ollama.com، ونزّل نموذجاً (`ollama pull <الاسم>`)، واكتب اسمه في الإعدادات، واضغط «فحص اتصال Ollama». لا تفعّل خيار الصور إلا لنموذج يفهم الصور.
- **هجين**: يجرّب المحلي أولاً، وإن فشل أو لم يتأكد (اختار «أخرى» أو قسماً غير معروفاً) أرسل الشكوى إلى Claude. الشكاوى المصحوبة بصور تذهب مباشرة إلى Claude ما لم يكن النموذج المحلي يدعم الصور.

## أبسط طريقة لدمج إعدادات الزبون في تطبيق المواطن (بدون Base64 أو أسرار)
1. نزّل `google-services.json` من Firebase (تطبيق أندرويد `com.shakawi.citizen`).
2. غيّر اسمه إلى `fb_config.json`.
3. في GitHub افتح المجلد `citizen-app/app/src/main/assets` ← **Add file ← Upload files** ← ارفع الملف ← Commit. (يُفضّل أن يكون المستودع **Private**.)
4. شغّل Actions ← Run workflow، وحمّل `citizen-app-apk`.
لكل زبون جديد استبدل هذا الملف بملف مشروعه ثم أعد البناء. وإن وُجد السر `CITIZEN_GOOGLE_SERVICES` فإنه يحل محل الملف.

## موظف بأكثر من قسم
في مستند الموظف داخل المجموعة `staff` يمكن استعمال أحد الشكلين:
- قسم واحد: الحقل `department` (string).
- أكثر من قسم: الحقل `departments` (النوع **array**) وفيه أسماء الأقسام، مثل: `البلدية` و`المياه`. الأسماء تطابق قائمة الأقسام حرفاً بحرف.
بعد التحديث انشر `firestore.rules` الجديدة، وأعد بناء تطبيق الموظف.

## تقارير الصيانة والفروع
- **الفروع**: في مستند الموظف داخل `staff` أضف الحقل `branches` (النوع **array**) وفيه أسماء فروع القسم، مثل `فرع الكرادة` و`فرع الأعظمية`.
- **تقرير الموظف للمدير**: في تطبيق الموظف يفتح الشكوى ويختار الفرع المسؤول، ثم «ممكن صيانتها» (ويكتب المواد المطلوبة) أو «غير ممكن»، ثم «إرسال التقرير للمدير».
- **في برنامج الحاسوب**: يظهر التقرير على بطاقة الشكوى، وتبويب **تقارير الفروع** يعرض لكل قسم: عدد الفروع، وكم فرعاً لديه عمل متبقٍ، وكم فرعاً أنجز، وكم شكوى ممكن صيانتها وغير ممكن.
- بعد التحديث: انشر `firestore.rules` الجديدة، وأعد بناء تطبيق الموظف وبرنامج الحاسوب.

## الإدخال اليدوي في برنامج الحاسوب
تبويب **إدخال يدوي** لتسجيل شكوى وردت هاتفياً أو بمراجعة شخصية: العنوان والتفاصيل واسم المواطن والهاتف وصورة (اختيارية). عند ترك القسم على «تحليل وتوجيه تلقائي» تُحلَّل الشكوى كالمعتاد، وعند اختيار قسم تُوجَّه إليه مباشرة بالأولوية المختارة، فتظهر عند موظفي ذلك القسم.

## بدون مصفوفات (array)
- **القسم**: حقل `department` من نوع string، وحساب لكل قسم. هذا يعمل مع القواعد كما هي. (المصفوفة `departments` ضرورية فقط إن أردت موظفاً واحداً بعدة أقسام.)
- **الفروع**: أحد الشكلين بدل المصفوفة: نص في الحقل `branches` مفصول بفواصل، مثل `فرع الكرادة، فرع الأعظمية`، أو حقل `branch` بفرع واحد لكل حساب.

## كوادر الصيانة الميدانية
لكل قسم عدة كوادر تخرج للصيانة (مثل «كادر 1» و«كادر 2»).
- **التعريف**: في مستند الموظف داخل `staff` أضف الحقل `crews` (نص مفصول بفواصل) مثل `كادر 1، كادر 2، كادر 3`، أو الحقل `crew` بكادر واحد. (المصفوفة مدعومة أيضاً لكنها غير لازمة.) يكفي وضعها في حساب واحد من القسم، وتُجمع كوادر كل حسابات القسم.
- **الإسناد**: في تطبيق الموظف يفتح الشكوى ويختار «كادر الصيانة الميداني» ثم «إسناد للكادر». تصبح الشكوى «قيد المعالجة» تلقائياً، ويمكن تغيير الكادر لاحقاً.
- **المتابعة**: بطاقة الشكوى تعرض الكادر المسؤول. وفي تبويب **تقارير الفروع** جدول «كوادر الصيانة» لكل قسم: عدد الكوادر، المشغول والمتاح، وعدد المُسند والمتبقي والمنجز لكل كادر، وعدد الشكاوى غير المُسندة.
- بعد التحديث: انشر `firestore.rules` الجديدة، وأعد بناء تطبيق الموظف وبرنامج الحاسوب.

## الإصدارات والتحديث بدون حذف التطبيق
- كل بناء في GitHub Actions يأخذ **رقم إصدار تلقائياً** (versionCode = رقم التشغيل، وversionName مثل `1.0.12`). لا تغيّر شيئاً يدوياً.
- التطبيقان يُوقَّعان الآن بمفتاح **ثابت** في `keystore/shakawi.jks`، فيُثبَّت الـ APK الجديد **فوق القديم** وتبقى البيانات وتسجيل الدخول.
- **مرة واحدة فقط**: التطبيقات المثبتة من النسخ السابقة موقّعة بمفتاح مختلف، فاحذفها يدوياً مرة واحدة ثم ثبّت الجديد. كل التحديثات بعدها بلا حذف.
- لا تحذف ملف `keystore/shakawi.jks` ولا تغيّره أبداً، وإلا عاد التحديث يتطلب حذف التطبيق. احتفظ بنسخة منه.
- رقم الإصدار يظهر في تطبيق الموظف ← تبويب «حسابي».
- المفتاح مناسب للتوزيع المباشر. للنشر على Google Play أنشئ مفتاحاً خاصاً وحافظ عليه سراً.

## الإشعارات والموقع والصور والتقييم والسجل والتكرار (v14)
- **الإشعارات**: عند توجيه شكوى يصل موظفي القسم إشعار فوري. وعند تغيّر حالة شكوى المواطن (تم التوجيه، قيد المعالجة، تم الحل) أو إسناد كادر يصله إشعار. الإرسال من برنامج الحاسوب (يجب أن يبقى مفتوحاً ومتصلاً)، ويظهر الإشعار عندما يكون التطبيق في الخلفية أو مغلقاً. يطلب التطبيق إذن الإشعارات عند أول فتح (وافق عليه).
- **الموقع**: في تطبيق المواطن زر «إرفاق موقعي الحالي» قبل الإرسال. في تطبيق الموظف وبرنامج الحاسوب زر «فتح الموقع على الخريطة».
- **صورة بعد الصيانة**: يرفعها الموظف من نافذة الشكوى، وتظهر للمواطن في «شكاواي» وفي برنامج الحاسوب.
- **تقييم المواطن**: بعد «تم الحل» يقيّم من 1 إلى 5 مرة واحدة. يظهر متوسط تقييم كل قسم وكل كادر في تبويب «تقارير الفروع».
- **سجل الشكوى**: من استلمها وأسندها وأنهاها ومتى. يظهر داخل نافذة الشكوى في تطبيق الموظف، وزر «سجل الشكوى» في برنامج الحاسوب.
- **كشف التكرار**: عند التوجيه تُقارَن الشكوى بشكاوى نفس القسم غير المنتهية خلال 14 يوماً (قرب جغرافي 150م أو تشابه نص كبير). تُعلَّم الجديدة «مكررة» وتزداد عدّادات الأصلية «تكررت N مرة».
- **للتفعيل**: انشر `firestore.rules` الجديدة، وأعد بناء التطبيقين وبرنامج الحاسوب (ثم أعد تثبيت برنامج الحاسوب). في Firebase تأكد أن **Cloud Messaging API (V1)** مفعّل (يكون مفعّلاً افتراضياً في المشاريع الجديدة).

## الخط الزمني للشكوى (v15)
على بطاقة كل شكوى في برنامج الحاسوب: وقت وصولها، وتوجيهها، واستلام الكادر لها، وبدء المعالجة، ووقت الإنجاز، مع **مدة الإنجاز** (من استلام الكادر إلى الإنجاز) والمدة الكلية، وللشكاوى غير المنتهية «مضى على الشكوى كذا». وفي جدول كوادر الصيانة عمود **متوسط زمن الإنجاز** لكل كادر. الشكاوى القديمة قبل هذا الإصدار قد لا تظهر فيها أوقات البدء والإنجاز الدقيقة. انشر `firestore.rules` وأعد بناء تطبيق الموظف وبرنامج الحاسوب.

## تغيير أولوية شكوى بعينها (v16)
في برنامج الحاسوب على بطاقة أي شكوى موجَّهة وغير منتهية قائمة **«تغيير الأولوية»**. عند رفعها إلى «عاجلة» أو «عالية» يصل موظفي القسم إشعار فوري، ويُسجَّل التغيير في سجل الشكوى. الشكاوى العاجلة تظهر بإطار أحمر 🚨. وفي برنامج الحاسوب وتطبيق الموظف تُرتَّب الشكاوى الأكثر إلحاحاً أولاً.

## الأعمال المنجزة (v17)
في تطبيق الموظف قسم **«الأعمال المنجزة»** داخل نافذة الشكوى: يكتب الموظف ملخص العمل في خانة الرد، ويرفق صورة بعد الصيانة (اختيارية)، ثم **«إرسال الإنجاز للمواطن والمدير»**؛ فتنتهي الشكوى ويصل المواطن إشعار، ويظهر الرد والصورة ووقت الإنجاز للمدير في برنامج الحاسوب. ولم يعد زر «تم الحل» منفصلاً. بعد الإنجاز **تختفي خيارات الإسناد وتقرير الصيانة**، ويبقى عرض ما أُنجز فقط. تبويب «المنتهية» أصبح «المنجزة».

## نافذة الكوادر المشغولة (v18)
- **برنامج الحاسوب**: تبويب **«الكوادر المشغولة»**: عدد الكوادر المشغولة والمتاحة، وكل كادر مشغول مع أعماله الجارية (عنوان الشكوى، الأولوية، الفرع، وقت الاستلام والمدة المنقضية، وزر الموقع على الخريطة)، والكوادر المتاحة لكل قسم. تتحدث النافذة تلقائياً.
- **تطبيق الموظف**: عند إسناد شكوى يظهر بجانب كل كادر 🔴 مشغول (عدد أعماله) أو 🟢 متاح.
- الكادر المشغول = له شكوى مُسندة غير منتهية. أعد بناء تطبيق الموظف وبرنامج الحاسوب.

## تصنيف الشكاوى والأعمال المنجزة (v19)
- **تصنيف الشكاوى** (برنامج الحاسوب): تصنيف حسب اليوم (التاريخ) أو الأسبوع أو الشهر أو يوم الأسبوع أو فترة اليوم أو القسم أو الحالة أو الأولوية أو الكادر أو الفرع أو سرعة الإنجاز أو تقييم المواطن أو المكررة. مع فلاتر الحالة والقسم ومن/إلى تاريخ والبحث. كل مجموعة قابلة للطي مع عدد منجزاتها.
- **الأعمال المنجزة**: قائمة بكل الأعمال المنتهية الأحدث إنجازاً أولاً، مع ملخص العمل والكادر ومدة الإنجاز والتقييم وصورتي **قبل** و**بعد**. فلتر بالقسم والتاريخ، وخيار «مع صورة فقط». الضغط على أي صورة يكبّرها.
- **إصلاح الإنجاز في تطبيق الموظف**: لا تُغلق النافذة إلا بعد تأكيد الخادم، ويظهر سبب أي فشل بوضوح، وتبقى بيانات النموذج والصورة المختارة إن أُعيد تشغيل الشاشة أثناء اختيار الصورة. إن ظهر «رُفض الإرسال» فانشر `firestore.rules` من هذا المشروع.

## حساب لكل كادر (v20)
- **إنشاء عدة كوادر دفعة واحدة**: في النموذج نفسه خانة «عدد الكوادر»؛ بقيمة 3 مثلاً والاسم «كادر» والبريد `crew@example.com` تُنشأ: كادر 1 / crew1@example.com، كادر 2 / crew2@example.com، كادر 3 / crew3@example.com بنفس كلمة المرور (حتى 30). يظهر نتيجة كل حساب، ويمكنك إعادة العملية بأسماء أخرى لإضافة المزيد.
- **إنشاء الحساب**: برنامج الحاسوب ← تبويب «الكوادر المشغولة» ← نموذج «إنشاء حساب كادر ميداني» (القسم، اسم الكادر، البريد، كلمة المرور). يُنشأ مستخدم Authentication ومستند `staff` فيه `role: "crew"` و`crew` و`department`. (يدوياً: أنشئ المستخدم ثم مستنداً في `staff` بهذه الحقول.) يجب أن يطابق اسم الكادر المُسند للشكاوى حرفاً بحرف.
- **ماذا يرى الكادر**: في تطبيق الموظف نفسه، شكاواه المُسندة إليه فقط (يمنع ذلك `firestore.rules`). يضغط **«📍 وصلت إلى الموقع»** فتبدأ المعالجة ويُسجَّل وقت الوصول ويصل المواطن إشعار، ثم يُرسل **الإنجاز** بالصورة. لا يستطيع إسناد الكادر ولا تغييره.
- **الإشعارات**: عند إسناد شكوى لكادر يصل حسابه إشعار (يتطلب بقاء برنامج الحاسوب مفتوحاً).
- **المتابعة**: وقت وصول الكادر يظهر في الخط الزمني للشكوى في برنامج الحاسوب.
- انشر `firestore.rules` الجديدة، وأعد بناء تطبيق الموظف وبرنامج الحاسوب.

## إضافة كوادر الأقسام من الحاسوب (v22)
تبويب «الكوادر المشغولة» ← بطاقة **«🧰 كوادر الأقسام»**: اختر القسم واكتب أسماء الكوادر مفصولة بفاصلة ثم «إضافة»؛ وبجانب كل كادر زر ✖ للحذف. تُحفظ الأسماء تلقائياً في الحقل `crews` لدى كل موظف قسم (غير حسابات الكوادر)، فتظهر في قائمة الإسناد بتطبيق الموظف دون تعديل Firestore يدوياً. الحذف من القائمة لا يحذف حساب الكادر ولا شكاواه السابقة. يلزم وجود حساب موظف واحد على الأقل للقسم.

## تخصيص اسم المسؤول (v23)
لكل حساب كادر (أو موظف) حقل `name` للاسم الشخصي. يُدخل عند إنشاء حساب الكادر («اسم المسؤول»)، أو يُعدَّل لاحقاً من قائمة «الحسابات الحالية» في تبويب «الكوادر المشغولة» (زر «حفظ الاسم»). يظهر في بطاقات الشكاوى والأعمال المنجزة والخط الزمني بجانب اسم الكادر، وفي **سجل الشكوى** بدل البريد الإلكتروني (من تطبيق الموظف)، وفي «حسابي».

## كل الإدارة من الحاسوب بلا Firebase Console (v24)
- **كوادر الأقسام** تُحفظ الآن في مجموعة `deptCrews` (وثيقة لكل قسم) ولا تحتاج حساب موظف مسبقاً. تقرؤها تطبيقات الموظفين تلقائياً (القاعدة الجديدة في `firestore.rules`).
- **إنشاء حساب موظف قسم** من تبويب «الكوادر المشغولة» ← بطاقة «👤 إنشاء حساب موظف قسم».
- مع «إنشاء حساب كادر» و«تخصيص الاسم» لا حاجة لأي تعديل يدوي في Firebase لإدارة الأقسام والموظفين والكوادر. انشر `firestore.rules` مرة واحدة بعد هذا التحديث.

## إدارة الحسابات من الحاسوب (v25)
لكل حساب (موظف قسم أو كادر) في تبويب «الكوادر المشغولة»: **حفظ الاسم**، **تغيير كلمة المرور** (لمن نسيها)، **تعطيل/تفعيل** الحساب (يُمنع من الدخول فوراً)، **حذف**. لا يحذف حذف الحساب الشكاوى السابقة. انشر `firestore.rules` الجديدة (فيها منع الحسابات المعطّلة).

## الفرز والصفحات في الحاسوب (v26)
قوائم «الجديدة» و«الموجّهة» و«تصنيف الشكاوى» و«الأعمال المنجزة» مقسّمة إلى **صفحات** (10 / 20 / 50 / 100 في الصفحة) مع أزرار التنقل (« السابق 1 2 3 التالي ») ومعلومة «عرض 21 – 40 من 135» أعلى القائمة وأسفلها. وفيها **فرز**: الأهم أولاً، الأحدث، الأقدم، الأولوية، القسم، الحالة، الكادر، الأقدم غير المنجزة؛ وللأعمال المنجزة: الأحدث/الأقدم إنجازاً، الأسرع/الأبطأ، الأعلى/الأقل تقييماً. تعود القائمة إلى الصفحة الأولى عند تغيير الفلاتر أو الفرز.

## تصنيف الشكوى عند الإرسال (v27)
في تطبيق المواطن خيار **«نوع الشكوى (اختياري)»**: أزرار بأسماء الأقسام (القائمة نفسها في إعدادات برنامج الحاسوب، تُنشر تلقائياً في المجموعة `config`). إن اختار المواطن نوعاً غير «أخرى» **وُجِّهت الشكوى إلى ذلك القسم مباشرة**، ويبقى الذكاء الاصطناعي يحدد الأولوية والملخص؛ وإن اقترح قسماً مختلفاً يُسجَّل اقتراحه في السجل وتُعتمد اختيار المواطن. وإن تعذّر التحليل (لا إنترنت أو مفتاح) تُوجَّه الشكوى بالنوع المختار بأولوية متوسطة. يظهر النوع المختار على بطاقة الشكوى في الحاسوب. إن لم يختر المواطن شيئاً أو اختار «أخرى» فالتوجيه بالتحليل كالمعتاد. انشر `firestore.rules`، وأعد بناء تطبيق المواطن وبرنامج الحاسوب، وافتح البرنامج مرة ليُنشر قائمة الأقسام.

## لوحة أداء الكوادر (v28)
تبويب **«أداء الكوادر»** في برنامج الحاسوب: الفترة (اليوم، 7 أيام، هذا الشهر، الشهر الماضي، الكل، أو من/إلى تاريخ) والقسم. تعرض: أبرز الكوادر (🏆 الأكثر إنجازاً، ⚡ الأسرع إنجازاً، 🏃 الأسرع استجابة، ⭐ الأعلى تقييماً) وجدولاً مرتّباً لكل كادر: المنجزة (مع شريط)، المُسندة، قيد العمل، نسبة الإنجاز، متوسط زمن الإنجاز، متوسط زمن الاستجابة (من الإسناد حتى وصول الكادر للموقع)، ومتوسط تقييم المواطنين. الضغط على عنوان أي عمود يعيد الترتيب، والميداليات 🥇🥈🥉 للثلاثة الأوائل. الأعمال المحسوبة هي المُسندة للكادر خلال الفترة. يظهر الكادر ولو لم يستلم شيئاً، فتعرف الكوادر الخاملة.

## تشخيص الإنجاز وتحميل الشكاوى (v29)
- كان تطبيق الموظف **يتجاهل أخطاء تحميل الشكاوى** (فتبقى القائمة فارغة دون سبب). صار يعرض الخطأ بوضوح (مثل رفض الصلاحيات) في القائمة وفي «حسابي» مع عدد الشكاوى الظاهرة للحساب.
- فشل «إرسال الإنجاز» يظهر في رسالة (Toast) وتحت الزر.
- صورة بعد الصيانة تُصغَّر تلقائياً حتى ~250KB لئلا يتجاوز المستند 1MB.
- قاعدة الكادر في `firestore.rules` بُسّطت لتتوافق مع استعلامات Firestore.

## تأكيد المواطن للإنجاز (v30)
بعد «تم الحل» يسأل تطبيق المواطن: **«هل تم حل المشكلة فعلاً؟»**.
- **✅ نعم**: تُسجَّل شكوى «مؤكَّدة» ✔ وتظهر عندها نجوم التقييم. يرى الموظف والمدير علامة التأكيد.
- **❌ لا**: يكتب السبب (اختياري) فتُعاد الشكوى **إلى القسم** (حالة «تم التوجيه») مع بقاء الكادر وصورة الإنجاز السابقة، وتُمسح علامة وصول الكادر ليصل من جديد. يصل موظفي القسم والكادر إشعار «🔁 أُعيد فتح شكوى»، وتظهر بأعلى القائمة بالأحمر في تطبيق الموظف، ويُسجَّل ذلك في سجل الشكوى. حد أقصى 3 مرات لكل شكوى.
- **برنامج الحاسوب**: علامات «✔ أكّد المواطن» و«🔁 أُعيد فتحها N مرة — السبب»، وصف تصنيف جديد «تأكيد المواطن»، وعمود **«أُعيد فتحها»** في لوحة أداء الكوادر (مؤشر جودة)، وسطر في الخط الزمني. الإشعارات من الحاسوب تتطلب أن يبقى مفتوحاً.
- انشر `firestore.rules` الجديدة، وأعد بناء التطبيقين وبرنامج الحاسوب.

## مراحل الشكوى والمواد (v31)
- **إشعار تقرير الكشف**: عند إرسال الكادر/الموظف تقرير الكشف (ممكن/غير ممكن + المواد) يصل **المدير إشعار نظام** على الحاسوب مع سطر في الشريط السفلي، ويصل موظفي القسم إشعار. يُنبَّه المدير أيضاً عند إعادة فتح شكوى.
- **تجهيز المواد**: زر **«📦 تم تجهيز المواد»** لموظف القسم (تطبيق الموظف) أو المدير (بطاقة الشكوى بالحاسوب)؛ يصل الكادر إشعار ويظهر له «✅ المواد جاهزة»، وإلا يرى «⏳ بانتظار تجهيز المواد». في حالة «غير ممكن الصيانة» يظهر «بانتظار قرار الإدارة».
- **شريط المراحل**: استُلمت › وُجِّهت › أُسندت › الكشف › المواد › الإنجاز؛ في الحاسوب (شرائح ملوّنة) وتطبيق الموظف والكادر. وللمواطن تتبّع مبسّط: استُلمت › وُجِّهت للقسم › أُسندت لكادر الصيانة › وصل الكادر › أُنجزت.
- الخط الزمني في الحاسوب فيه تقرير الكشف وتجهيز المواد. انشر `firestore.rules` وأعد بناء التطبيقات والحاسوب.

## التصميم الجديد لبرنامج الحاسوب (v32)
واجهة احترافية مجسَّمة: شريط جانبي داكن بأيقونات وعدّادات (جديدة / قيد المعالجة)، شريط علوي بعنوان الصفحة ومؤشرات سريعة (جديدة، قيد المعالجة، عاجلة مفتوحة، منجزة اليوم)، بطاقات بظلال متعددة الطبقات وتأثير ارتفاع عند التمرير وحافة ملوّنة حسب حالة الشكوى (والعاجلة بالأحمر)، وأزرار ثلاثية الأبعاد تغوص عند الضغط، وحقول غائرة، وجداول بصفوف متبادلة وترويسة قابلة للفرز، وشرائح مدرّجة، ووضع داكن تلقائي حسب إعداد ويندوز، وتكيّف مع الشاشات الأضيق (أيقونات فقط). لا تغيير في الوظائف.
